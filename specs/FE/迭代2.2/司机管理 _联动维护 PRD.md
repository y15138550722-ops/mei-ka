# 司机管理联动维护 PRD

**版本**: v1.0
**最后更新**: 2026-06-02
**作者**: Codex

---

## 1. 背景与目标

### 1.1 业务背景

当前客服或运营人员在处理司机资料核查、车辆资料补录与日常维护时，通常会先进入司机管理确认司机资料是否已录入，再根据司机绑定的车牌号跳转到车辆管理，继续核查对应车辆的审核状态、未通过原因以及车身照片是否已上传。

该流程本质上是围绕“司机与绑定车辆资料联合核查”的高频操作，但现有系统将司机信息维护与车辆资料维护拆分在两个页面中完成，导致一线人员需要在多个页面之间来回切换。

### 1.2 问题陈述

- 司机管理中只能看到基础绑定车辆信息，无法直接查看绑定车辆审核状态。
- 司机管理中无法直接查看车辆审核未通过原因，问题定位效率低。
- 司机管理中无法判断绑定车辆车身照片是否已上传，容易遗漏补录。
- 如需补录或更新车辆资料，还需再跳转到车辆管理中单独操作，操作路径较长。

### 1.3 建设目标

在司机管理中直接展示绑定车辆的审核状态、未通过原因及车身照片上传情况，并支持在编辑司机信息时快捷维护绑定车辆相关资料，包括补充或更新车身照片，减少跨页面重复查询和操作，提升客服及运营人员日常核查、补录与维护效率。

## 2. 现状洞察（AS-IS）

| 痛点         | 描述                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 信息割裂     | 司机资料与绑定车辆审核资料分散在司机管理、车辆管理两个页面。             |
| 查询链路长   | 核查一次司机绑定车辆情况，需要先查司机，再切换到车辆管理查车牌对应车辆。 |
| 补录动作分散 | 发现车辆资料缺失后，无法在当前司机上下文中直接补录。                     |
| 易漏查漏补   | 页面切换频繁，容易遗漏未通过原因或照片缺失项。                           |
| 处理效率低   | 高频核查与维护动作路径长，增加客服/运营处理时长。                        |

## 3. 目标（TO-BE）与非目标

### 3.1 目标

| # | 目标                 | 描述                                                     |
| - | -------------------- | -------------------------------------------------------- |
| 1 | 车辆审核信息前置展示 | 在司机管理中直接展示绑定车辆审核状态。                   |
| 2 | 未通过原因直接可见   | 对审核未通过车辆展示未通过原因，减少二次查询。           |
| 3 | 照片上传情况可见     | 在司机管理中展示车身照片上传情况，便于快速判断是否缺失。 |
| 4 | 快捷维护车辆资料     | 在编辑司机信息时支持快捷补录、更新绑定车辆资料。         |
| 5 | 减少跨页面操作       | 尽量在司机管理内完成核查与常见补录动作。                 |

### 3.2 非目标（本期不做）

- 不替代完整车辆管理页面的全部能力。
- 不新增车辆审核流程本身，仅补充展示与快捷维护能力。
- 不支持在司机管理中切换复杂车辆档案配置项，仍以常用补录字段为主。
- 不改变司机与车辆现有绑定关系规则。

### 3.3 User Stories

#### US-1：在司机管理中查看绑定车辆审核情况

> **作为** 客服或运营人员
> **我希望** 在司机管理中直接看到司机绑定车辆的审核状态、未通过原因和车身照片上传情况
> **以便于** 我无需跳转车辆管理也能完成日常核查

**验收标准**:

- 司机管理列表或详情中可直接查看绑定车辆审核状态。
- 当绑定车辆审核未通过时，可直接查看未通过原因。
- 可直接看到车身照片上传情况，至少能区分“已上传/未上传”。

#### US-2：在编辑司机信息时快捷维护绑定车辆资料

> **作为** 客服或运营人员
> **我希望** 在编辑司机信息时，可以一并维护绑定车辆资料
> **以便于** 我在同一操作链路内完成补录和更新

**验收标准**:

- 编辑司机信息时，存在绑定车辆资料快捷维护区域或入口。
- 支持补充或更新车身照片。
- 保存后可立即反馈更新结果，并在司机管理中展示最新状态。

## 4. 角色与使用场景

| 角色 | 核心诉求                       | 典型操作                           |
| ---- | ------------------------------ | ---------------------------------- |
| 客服 | 快速核查司机与车辆资料是否齐全 | 查司机、看绑定车状态、补照片       |
| 运营 | 批量处理资料补录与未通过修正   | 查未通过原因、补车辆资料、跟进复审 |

### 4.1 高频场景

1. 客服在司机管理中查看某司机资料时，需要同步确认该司机绑定车辆是否审核通过。
2. 运营发现司机绑定车辆审核未通过，需要立即查看未通过原因并补录缺失照片。
3. 客服在联系司机补资料后，希望在编辑司机信息时直接更新绑定车辆车身照片，无需再跳转车辆管理。

## 5. 功能需求

### 5.1 司机管理列表/详情增加绑定车辆信息展示

### 5.1.1 展示内容

在司机管理中，针对已绑定车辆的司机，增加以下车辆相关信息展示：

| 字段             | 展示要求     | 说明                             |
| ---------------- | ------------ | -------------------------------- |
| 绑定车牌号       | 保持现有展示 | 作为车辆识别主信息               |
| 车辆审核状态     | 新增展示     | 如：待审核、审核通过、审核未通过 |
| 未通过原因       | 条件展示     | 仅当审核状态为审核未通过时展示   |
| 车身照片上传情况 | 新增展示     | 如：已上传、未上传、部分上传     |

### 5.1.2 展示规则

- 当司机未绑定车辆时，车辆相关信息展示为“未绑定车辆”或 `--`。
- 当绑定车辆存在审核状态时，展示最新审核结果。
- 当审核状态为“审核未通过”时，未通过原因需直接可见，避免再次跳转查询。
- 车身照片上传情况需基于当前绑定车辆资料实时展示。

### 5.2 编辑司机信息时支持快捷维护绑定车辆资料

### 5.2.1 入口要求

- 在编辑司机信息弹窗、抽屉或详情编辑区域中，增加“绑定车辆资料”维护模块或快捷入口。
- 当司机已绑定车辆时，默认带出当前绑定车辆的基础信息与资料状态。
- 当司机未绑定车辆时，不展示车辆资料维护内容，或置灰并提示需先绑定车辆。

### 5.2.2 可维护内容

本期支持的快捷维护内容包括：

| 维护项           | 操作要求               |
| ---------------- | ---------------------- |
| 车辆审核状态查看 | 只读展示最新状态       |
| 未通过原因查看   | 只读展示最新未通过原因 |
| 车身照片补录     | 支持上传缺失车身照片   |
| 车身照片更新     | 支持替换已有车身照片   |

### 5.2.3 操作反馈

- 上传或更新车身照片后，需给予明确成功/失败反馈。
- 保存成功后，司机管理中的车辆照片上传情况需同步更新。
- 若上传失败，需提示失败原因，并支持重新上传。

### 5.3 快捷维护与车辆管理的数据一致性

- 在司机管理中维护的绑定车辆资料，应与车辆管理中的对应车辆资料保持一致。
- 在司机管理内完成照片补录或更新后，车辆管理页面中应同步可见最新结果。
- 若绑定车辆资料已被其他人更新，页面应展示最新状态，避免用户基于旧数据操作。

## 6. 页面交互要求

### 6.1 司机管理列表页

- 在现有司机管理列表中，为绑定车辆信息补充展示车辆审核状态和车身照片上传情况。
- 对于审核未通过车辆，支持直接查看未通过原因，减少额外点击层级。
- 若列表展示空间有限，可通过状态标签 + hover/展开说明方式承载未通过原因，但必须保证在司机管理页内可完成查看。

### 6.2 司机详情/编辑页

- 编辑司机信息时，应在同一界面内提供绑定车辆资料快捷维护区域。
- 该区域需清晰区分“只读状态信息”和“可编辑照片维护项”，避免误操作。
- 车身照片上传区需支持查看当前是否已上传，并执行补录或替换。

### 6.3 异常提示

- 无绑定车辆时，提示“当前司机未绑定车辆，暂无法维护车辆资料”。
- 车辆资料加载失败时，提示“车辆资料获取失败，请稍后重试”。
- 上传失败时，提示失败原因，如格式不支持、大小超限、网络异常等。

## 8. 业务规则与校验

| 规则编号 | 规则名称 | 规则描述                                                             |
| -------- | -------- | -------------------------------------------------------------------- |
| BR-001   | 绑定前置 | 仅已绑定车辆的司机可展示和维护车辆资料。                             |
| BR-002   | 状态一致 | 司机管理中展示的车辆审核状态、未通过原因、照片状态需与车辆管理一致。 |
| BR-003   | 条件展示 | 未通过原因仅在审核状态为审核未通过时展示。                           |
| BR-004   | 权限一致 | 仅具备司机资料编辑权限的角色，才可在编辑司机时维护车辆资料。         |
| BR-005   | 照片校验 | 车身照片上传需符合系统既有格式、数量、大小校验规则。                 |
| BR-006   | 实时反馈 | 上传或更新车身照片后，需返回明确结果并刷新最新状态。                 |

## 9. 验收标准

| 编号   | 验收项                   | 验收标准                                               |
| ------ | ------------------------ | ------------------------------------------------------ |
| AC-001 | 司机管理可见车辆审核状态 | 在司机管理中可直接看到绑定车辆审核状态。               |
| AC-002 | 司机管理可见未通过原因   | 当车辆审核未通过时，可在司机管理中直接查看未通过原因。 |
| AC-003 | 司机管理可见车身照片状态 | 在司机管理中可直接判断车身照片是否已上传。             |
| AC-004 | 编辑司机时可维护车辆照片 | 编辑司机信息时，可直接补录或更新绑定车辆车身照片。     |
| AC-005 | 数据同步一致             | 在司机管理内完成维护后，车辆管理中同步展示最新结果。   |
| AC-006 | 异常提示明确             | 无绑定车辆、加载失败、上传失败等场景均有明确提示。     |

## 10. 边界场景

| 场景                     | 处理要求                                         |
| ------------------------ | ------------------------------------------------ |
| 司机未绑定车辆           | 不展示可维护车辆资料，提示先绑定车辆。           |
| 绑定车辆已删除或异常     | 展示异常提示，避免进入错误维护流程。             |
| 审核通过但无照片         | 按实际照片状态展示，不因审核状态掩盖资料缺失。   |
| 照片部分上传             | 需明确标记“部分上传”，便于继续补录。           |
| 保存过程中资料被他人更新 | 优先提示数据已变更，并刷新最新数据后再继续操作。 |

## 11. 预期收益

- 减少司机管理与车辆管理之间的来回跳转。
- 缩短客服、运营人员完成一次资料核查与补录的操作路径。
- 降低漏查、误判和遗漏补录的风险。
- 提升司机与车辆资料维护效率，优化日常使用体验。
