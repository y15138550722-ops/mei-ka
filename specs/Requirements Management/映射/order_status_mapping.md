# 订单状态映射关系

本文档用于说明 `用户端`、`管理端`、`生产端` 三套订单状态之间的对应关系。

## 1. 状态总表

| 触发场景 | 用户端 | 管理端 | 生产端 |

| --- | --- | --- | --- |

| 用户端提交待审核订单 | 待审核 | 待审核 | 无订单 |

| 管理端审核通过 | 制作中 | 待制作 | 未翻译 |

| 管理端审核拒绝 | 已取消 | 已取消 | 无订单 |

| 生产端翻译订单后 | 制作中 | 待制作 | 未制作 |

| 生产端导出 PDF 后 | 制作中 | 待制作 | 未发货 |

| 生产端发货后 | 已发货 | 已发货 | 已发货 |

| 生产端取消订单 | 已取消 | 已取消 | 已取消 |

## 2. 分层映射

### 2.1 用户端 -> 管理端

```json

{

  "待审核": ["待审核"],

  "制作中": ["待制作"],

  "已取消": ["已取消"],

  "已发货": ["已发货"]

}

```

### 2.2 管理端 -> 生产端

```json

{

  "待审核": ["无订单"],

  "待制作": ["未翻译", "未制作", "未发货"],

  "已取消": ["无订单", "已取消"],

  "已发货": ["已发货"]

}

```

### 2.3 生产端 -> 管理端 -> 用户端

```json

{

  "未翻译": { "admin": "待制作", "user": "制作中" },

  "未制作": { "admin": "待制作", "user": "制作中" },

  "未发货": { "admin": "待制作", "user": "制作中" },

  "已发货": { "admin": "已发货", "user": "已发货" },

  "已取消": { "admin": "已取消", "user": "已取消" }

}

```

## 3. 订单关系说明

1.`待审核` 仅存在于用户端和管理端，生产端无订单。

2. 管理端审核通过后，管理端进入 `待制作`，用户端显示 `制作中`，生产端初始为 `未翻译`。
3. 管理端审核拒绝后，管理端和用户端都变为 `已取消`，生产端无订单。
4. 生产端 `翻译订单`、`导出 PDF` 都属于 `待制作` 阶段的不同过程状态，对应用户端统一显示 `制作中`。
5. 生产端 `发货` 后三端统一为 `已发货`。
6. 生产端 `取消订单` 后三端统一为 `已取消`。

## 4. 落库建议

建议使用多行映射表存储，不要把一对多状态压成单值字段。

示例结构：

```json

[

  { "user": "待审核", "admin": "待审核", "production": null },

  { "user": "制作中", "admin": "待制作", "production": "未翻译" },

  { "user": "制作中", "admin": "待制作", "production": "未制作" },

  { "user": "制作中", "admin": "待制作", "production": "未发货" },

  { "user": "已取消", "admin": "已取消", "production": null },

  { "user": "已取消", "admin": "已取消", "production": "已取消" },

  { "user": "已发货", "admin": "已发货", "production": "已发货" }

]

```
